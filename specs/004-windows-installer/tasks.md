# Tasks: Windows Installer

**Input**: Design documents from `/specs/004-windows-installer/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Tests**: MANDATORY (Constitution VII, spec FR-010–FR-012, FR-026): content verification,
installer-message parity test and the install/upgrade/uninstall smoke test are deliverables.

**Organization**: app-side prerequisites (version, icon, notices, mutex, trimmed publish) are
Foundational; US2 (verified build) comes before US1 because the installer is compiled from the
verified folder; US3–US5 add upgrade, uninstall and silent behaviour to the same script and the
smoke test.

## Dependencies & Execution Order

```text
Setup (T001–T003) → Foundational (T004–T008)
  → US2 verified build (T009–T013)
  → US1 install (T014–T017)
  → US3 upgrade (T018–T020) → US4 uninstall (T021–T022) → US5 unattended (T023–T024)
  → Polish (T025–T027)
```

- US2 before US1: the installer compiles from the verified publish folder and the build script.
- US3/US4/US5 extend the same `.iss` and smoke-test script, so they run in order.
- T013 (CI) can land with US2; its `-SmokeTest` run becomes meaningful after T019/T022.

## Parallel Opportunities

```text
Setup:        T002 | T003
Foundational: T005 | T006 | T007 (then T008)
US1:          T014 | T016
Polish:       T025 | T026
```

## Implementation Strategy

1. **Foundational first**: version, icon, notices, mutex and the trimmed publish are needed by
   every story and change the app itself — verify the app still works before packaging.
2. **MVP** = US2 + US1: a verified installer that installs and runs in six languages.
3. Then upgrade/downgrade (US3), uninstall (US4), silent mode (US5) — each adds smoke-test steps.
4. PR `004-windows-installer` → `main` when the CI `installer` job is green; tag `windows-v0.2.0`
   after merge.
